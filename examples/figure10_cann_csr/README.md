## Constitutive evaluation-cost benchmark (Table 8)
`benchmark_evaluation_cost.py` (run in WSL, NN venv) times (dPsi/dI1, dPsi/dI2) for the trained 8-neuron
Softplus CANN (nn_cache/output/NN_output/ffbp_model.pt, 33 params) vs the exported symbolic law
(material_package.json), single thread, float64, Intel Core Ultra 5 235.
Both modes now use the same 1e6 invariant samples (vectorized: all points in one call; pointwise: one call
per point, results dropped so the three evaluators share one loop harness). The Python timings drift by some
tens of percent between processes, so the paper quotes medians of three runs:
`aggregate_evaluation_cost.py evaluation_cost_run{1,2,3}.json` -> evaluation_cost.json.
Medians: vectorized CANN autograd 129.9 ns, CANN closed-form NumPy 96.0 ns, SR 6.0 ns (21.5x for autograd);
pointwise CANN autograd 36.71 us, CANN closed-form scalar 0.967 us, SR 0.086 us (425x / 11x).
Only the PyTorch-autograd and symbolic rows are reported in Table 8.
Element evaluations: coarse 2,962 x 1,717,697 ~ 5.1e9; fine 7,706 x 2,257,221 ~ 1.7e10; the coarse count
projects to ~52 h (pointwise autograd) against ~7 min (symbolic law) on a single thread.

## In-Engine constitutive cost and robustness (Table 9, engine_cost/)
Benchmark Engine user libraries (both built by `build_cann_userlib.sh`):
- `engine_cost/luser01.f90` (generated by `make_cann_luser01.py` from the deployed
  `law291_userlib/luser01.f90`) evaluates the trained 8-neuron Softplus CANN in closed form
  (weights from nn_cache/output/NN_output/ffbp_model.pt) -> libraduser_cann291.so.
- `engine_cost/luser01_specialized.f90` (generated by `make_specialized_luser01.py` from the same
  deployed routine) evaluates the discovered law with its exponents fixed at build time (Horner form,
  coefficients read from nn_cache/material.flat) -> libraduser_spec291.so.
Both differ from the deployed routine only in the call that returns (dPsi/dI1, dPsi/dI2).
Smoke test either library with `smoke_test.sh <lib>` (0.002 s, expect NORMAL TERMINATION, 18,460 cycles).

- `run_fortran_bench.sh` + `bench_constitutive.f90`: material routines alone, 2e7 samples, gfortran -O3:
  specialized polynomial 0.79 ns/eval, CANN closed form 16.4 ns/eval, exported table 43.3 ns/eval
  -> CANN/specialized = 20.8. Log: bench_constitutive.log.
- `run_engine_cost_repeat3.sh` + `collect_repeats3.py` (Table 9): three-way interleaved Engine runs from the
  same restart file/deck, t <= 0.02 s, 8 threads, 5 repeats each (rep_table_*/, rep_spec_*/, rep_cann_*/).
  Cycles 184,733 for both symbolic routines (identical printed energies -> specialized == table) and 184,739
  for the CANN. Median element-block CPU per evaluation: spec 712.2, table 736.0, CANN 749.1 ns
  (spreads 700-729, 728-743, 727-755). Median elapsed: 91.7 / 94.0 / 94.0 s (spread ~3%). The CANN-minus-spec
  gap (36.9 ns/eval) is 5% of the element-block time, i.e. of the order of the run-to-run scatter; one
  element-cycle costs ~712 ns of element CPU, so the constitutive evaluation is <= 6% of it.
  Output: engine_cost_repeats3.json.
- `run_engine_cost_repeat.sh` + `collect_repeats.py`: earlier two-way (deployed table vs CANN) version of the
  same protocol, superseded by the three-way runs. Output: engine_cost_repeats.json.
- `run_engine_cost.sh`: single paired runs. t <= 0.10 s (run_symbolic/, run_cann/): 936,924 vs 936,353 cycles,
  466.6 vs 477.6 s, element CPU 2055 vs 2111 s (engine_cost.json). Full 0.18 s ramp (run_symbolic_full/,
  run_cann_full/): the symbolic run reproduces the production run (1,717,697 cycles, 844.1 s), while the
  CANN-driven run loses stability at t = 0.1188 s (nodal time step collapse, energy error -99.9%) after
  1,118,751 cycles (engine_cost_full.json).
- `extrapolation_check.py`: uniaxial nominal stress of the CANN peaks at lambda = 2.48 and turns negative
  beyond lambda ~ 2.7, just outside the calibration box (I1 <= 7.674 -> lambda <= 2.63); the exported
  polynomial stays monotone to lambda = 3.5, while the ligaments reach lambda1 = 2.60-2.82.
  Output: extrapolation_check.json.
